# CONFIG.MD — stapel-categories

Config registry for **stapel-categories** (`static-scaffold-and-config.md` §2).
One row per configuration key the module reads, its **source** (`env` = the
process environment / the `STAPEL_CATEGORIES` settings dict), what it is for,
whether it is required, and its default.

Every key is read through `categories_settings`
(`stapel_categories.conf.AppSettings`, namespace `STAPEL_CATEGORIES`).
Resolution order per key: `settings.STAPEL_CATEGORIES` dict → a flat Django
setting of the same name → environment variable → the default below.

stapel-categories hard-depends on **stapel-attributes** (the typed feature
engine it stores category schemas with); the scaffolder pulls attributes in
automatically as a headless pip dependency.

## stapel-categories

| Key | Source | Purpose | Required | Default |
|-----|--------|---------|----------|---------|
| CAROUSEL_CACHE_TIMEOUT | env | seconds the `categories/carousel` response is cached. | no | 300 |
| FEATURE_DISPLAY_CACHE_TIMEOUT | env | seconds an admin feature display-name translation is memoized. | no | 60 |
| FEATURE_RENAME_HOOK | env | name of the comm Function `load_catalog --rename-features` calls to move stored listing answers when a feature slug is renamed. `auto` = `listings.rename_feature_keys` if stapel-listings is installed, nothing otherwise; `none` disables it (the loader then refuses renames unless `--no-hook` is passed). | no | auto |
| DISPLAY_TRANSLATOR | env | dotted path to a `(key) -> str` callable rendering a translation key for admin/`__str__` display (REPLACE). Default is identity. | no | stapel_categories.translation.identity_translator |

## Catalogue fixture files (`<BASE_DIR>/fixtures/catalog/`)

Not settings — the files `export_catalog` writes and `load_catalog` reads.
Listed here because a producer outside this repo (an importer emitting a
catalogue) writes them.

| File | Required | Contents |
|------|----------|----------|
| `features.json` | yes | root Feature definitions, keyed by `slug`. |
| `categories.json` | yes | tree edges (`parent_slug`) + each category's materialized feature list. Optional per-record keys, written only when set: `children_as`, `children_axis_label`, `children_axis_tag`, `children_expand_by`, `external_id`, `external_source`, `comment`, `translatable`. |
| `links.json` | no | pointers between categories: `{source, target, source_external_id, target_external_id, order, label, external_source}`. Ends resolve by external id first, slug otherwise. A load rewrites only the `external_source` values this file names; every other author's links are left alone. An absent file touches no link. |
| `.sync-state.json` | no | content-hash sidecar, the 3-way base. Regenerated by every export and by every real load. |

A producer that changes how it derives slugs re-keys every record in
`categories.json` at once. `load_catalog --keep-slugs` loads such a file
without moving the live addresses: a category matched by
`(external_source, external_id)` keeps its live slug and takes every other
field, and the renames it holds are counted and named
(`slug renames HELD (--keep-slugs): N`) rather than applied or recorded. The
`links.json` ends addressed by slug alone follow the same holds. Feature slugs
are not covered — see `--rename-features` and `FEATURE_RENAME_HOOK` above.

## Optional resolver capability

`children_expand_by` on a feature with a **referential** type reads its
values through the registered stapel-attributes vocabulary resolver. The
declared `VocabularyResolver` protocol answers four questions about one code
and cannot list a level, so this module calls the OPTIONAL reader
`terms(vocabulary, level) -> [(code, label)]` when the resolver offers one. A
resolver without it yields no virtual children — never a guess.
